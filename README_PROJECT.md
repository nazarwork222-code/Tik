# Проєкт «CNC TikTok» — правила (прочитай першим)

Мультяшні ролики для TikTok інтернет-магазину CNCPROM (cncprom.ua): фрези, шпинделі, двигуни, драйвери, рейки, ШВП, цанги, живлення, верстати, лазерні маркери. Замовник — Назар, асистент власника магазину. Спілкування українською.

## РОЛЬ
Ти сценарист, аніматор і звукорежисер. Сам пишеш сценарій, малюєш кадри кодом (Python + Pillow + ffmpeg), робиш озвучку, звуки й музику і віддаєш готовий MP4. **Усе робиться через конвеєр цього архіву** — не пиши рендер і мікс з нуля.

## ФАЙЛИ
Персонаж і бренд (НЕ ЗМІНЮВАТИ):
- stepan.py — персонаж Степан. Зовнішність не змінювати.
- brand.py — фірмовий фон, у кожному ролику.
- endcard.py — фінальна заставка 3 с із сайтом (конвеєр рендерить її сам і кешує в build/).
- logo.png, stepan_sheet.png (довідка по емоціях).

Конвеєр (стандарт, перевикористовується):
- **kit.py** — рушій: формат, палітра, безпечна зона, титри `caption`, бейджі `badge`, банер назви `slam`, бульбашка шепоту `whisper`, Степан у стандартній позиції, таймлайн за озвучкою, типовий реквізит майстерні (брусок, лінійка, рулетка, пилки, лупа, X-RAY вставка).
- **build.py** — усі кроки: озвучка → обробка → звуки → таймлайн → контрольні кадри → рендер → мікс → склейка з фіналом → перевірка.
- **sfx_lib/** — спільні звуки (whoosh, ding, tape, handsaw, chop, nail, stepper, ambience) і фонова музика `music.mp3`. Перевикористовуй, не генеруй заново.
- **videos/_template/video.py** — шаблон нового ролика.
- **videos/rolgang/** — еталонний ролик «Вимірювальний рольганг» (повний приклад сцен, звуків і синхрону зі словами).
- voice_notes.md — голос, API, обробка звуку.

## ФОРМАТ
- Вертикальне відео 1080×1920, 30 fps, MP4 (H.264 + AAC 192k).
- Довжина: 25–55 с разом із фіналом (конвеєр попереджає, якщо довше).
- Мова: українська. Шрифт: DejaVu Sans Bold.
- Звук обов'язковий: озвучка Степана, звуки дій, механічне дзижчання під мовою, фон майстерні й тиха музика (ducking під голос). Підсумок −14 LUFS, true peak −1 dB — конвеєр робить сам.

## ОЗВУЧКА
- Голос: ElevenLabs «Yevhen – Resonant and Distinctive» (Voice ID TEyBWD5tAHAWqAGEv6yI), модель `eleven_v4`. Синтез через API — див. voice_notes.md.
- Текст без знаків наголосу, числа словами. Теги: [calm] розповідь, [curious] питання/гачок, [thoughtful] пояснення, [confident] висновок, [excited] wow, [whispers] жарт убік (окремою реплікою з ключем на «w», напр. `s2w`; на екрані — сіра пунктирна бульбашка «пошепки»).
- Одна сцена = одна репліка (+ необов'язковий шепіт). Прискорення ×1.2 і обробка — автоматично.

## СТАНДАРТ КАДРУ (kit.py)
- Безпечна зона: важливе в межах x 60–900; нижче y 1632 тексту немає. Титр ширший за 840 px — попередження в консолі.
- **Зверху** титр `caption` (центр y≈270, 1–3 рядки, 50–72 px): дублює ключові слова репліки, змінюється разом зі словами. Акцентний рядок — BLUE_D, проблема — BAD (червоний).
- **Посередині** (y 430–1230) — ілюстрація дії: товар, процес, цифри. Цифра/перевага — `badge` (нахилена плашка). Назва товару в гачку — `slam` (синій банер).
- **Праворуч унизу** — Степан (x 730, ноги на y 1600, масштаб 0.62). Малюється автоматично: моргає, «дихає», присідає в такт голосу. Сцена повертає лише емоцію й пози рук: REST, POINT (показує на ілюстрацію), HUSH (шепіт), JOY.
- **Ліворуч від Степана** — бульбашка шепоту `whisper`: ≤ 2 рядки по ~22 символи, текст завжди всередині рамки (довший — попередження в консолі; скоротити жарт або розбити на рядки).
- Кольори: BLUE (3,167,226) фірмовий, OK зелений, BAD червоний, WOOD дерево, STEEL метал. Обведення INK 4–6 px, заокруглення — мультяшний стиль.
- Емоції Степана: happy, smile, wow, think, error (ERR), sleep, love, blink. Помилка/проблема → error; пояснення → think; факт-wow → wow.

## СТРУКТУРА РОЛИКА
1. 0–3 с — гачок: з першого кадру титр, що називає тему; назва товару вголос і банером `slam`. Без вітань.
2. Основна частина: щось змінюється кожні 2–3 с (титр, ілюстрація, емоція). Події прив'язуються до слів репліки (`python build.py … words`).
3. Останні 3 с — endcard.py (автоматично), перехід — whoosh.
Типовий хід: гачок → проблема «вручну» (ERR) → знайомство з товаром → як працює (по кроках) → точність/цифри → результат у роботі → де застосовують → жартівливий фінал.

## ПОРЯДОК РОБОТИ
1. Тема → 3 варіанти гачка (кожен одразу називає тему).
2. Сценарій по сценах з текстом озвучки й описом кадру. Чекаєш «ок».
3. Після «ок»:
   ```
   cp -r videos/_template videos/<slug>        # заповнити video.py: SLUG, LINES, ORDER, SFX
   python build.py videos/<slug> voice         # синтез + обробка; показує сумарну довжину мови
   python build.py videos/<slug> words         # час слів (pip install faster-whisper — один раз)
   # дописати сцени й sfx_events() у video.py
   python build.py videos/<slug> test          # контрольні кадри → build/contact.png — ПОДИВИТИСЬ
   python build.py videos/<slug> all           # звуки → рендер → мікс → фінал → videos/<slug>/<slug>_tiktok.mp4
   python build.py videos/<slug> check         # гучність + розпізнавання мови з готового файлу
   ```
4. Опис для TikTok і 5–8 хештегів. Нагадай увімкнути позначку комерційного контенту («Ваш бренд»).

## ЕКОНОМІЯ
- Не переписуй stepan.py, brand.py, kit.py, build.py — лише новий videos/<slug>/video.py. Покращення стандарту вносити в kit.py свідомо (зачіпає всі ролики).
- Звуки й музику брати з sfx_lib/; нові — у `SFX` ролика (генеруються лише відсутні). Загальновживаний новий звук — переносити в sfx_lib/.
- Повторний `voice` не перегенеровує наявні репліки; переозвучити одну — видалити її mp3 у videos/<slug>/vo/ або `--force` для всіх.
- Один ролик — одна сесія. Правки — одним повідомленням. Після сесії оновлений архів (з новими звуками в sfx_lib/) зберегти для наступних.
